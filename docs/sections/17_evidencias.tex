Los manifiestos se verifican desde la carpeta correspondiente. En Linux y macOS, o en Windows desde Git Bash:

\begin{lstlisting}[language=bash,caption={Verificación de la integridad de los datos}]
cd data && sha256sum -c SHA256SUMS
cd lamport20 && sha256sum -c SHA256SUMS
\end{lstlisting}

Para revisar todos los manifiestos del repositorio de una sola vez:

\begin{lstlisting}[language=bash]
for f in $(find data docs/evidencias -name SHA256SUMS); do
  (cd "$(dirname "$f")" && sha256sum -c SHA256SUMS --quiet) || echo "FALLA: $f"
done
\end{lstlisting}

Los hashes de los cuatro CSV del benchmark se calcularon en Windows, con fin de línea CRLF. Para que coincidan en cualquier sistema operativo, el archivo \texttt{.gitattributes} indica a Git que conserve esos archivos sin convertir sus saltos de línea. El 21 de noviembre de 2026 se comprobaron, en un clon limpio del repositorio en Linux, los 77 manifiestos \texttt{SHA256SUMS} de \texttt{data/} y \texttt{docs/evidencias/}, sin ninguna falla.

\subsection{Historial Git y reproducción del trabajo}

Los commits significativos de cada integrante se enlazan en la tabla de aportes (tabla~\ref{tab:aportes}). El historial completo de un autor se puede consultar con:

\begin{lstlisting}[language=bash]
git log --author="Mera" --format="%h %ad %s" --date=short
\end{lstlisting}

Los comandos para reproducir el trabajo están en \texttt{README.md}. En resumen, desde la raíz del repositorio y con el entorno virtual activo:

\begin{lstlisting}[language=bash,caption={Reproducción de las pruebas, el análisis y el informe}]
python -m pip install -r requirements.txt
python analysis/run_lamport_experiment.py --mechanism grpc --run-id grpc-r99 --output data/lamport_grpc_r99
python analysis/analisis_resultados.py
python -B -m unittest discover -s tests
cd docs && pdflatex main.tex && biber main && pdflatex main.tex && pdflatex main.tex
\end{lstlisting}

El lanzador de tres nodos no sobrescribe carpetas existentes, por lo que cada repetición debe usar un \texttt{--run-id} y un \texttt{--output} nuevos. El script de análisis lee los CSV de \texttt{data/} sin modificarlos y regenera las tablas y figuras del informe.

\subsection{Demostración en vivo y video de respaldo}

Para la demostración en clase, cualquier integrante puede ejecutar un intercambio y cambiar el tamaño del mensaje en el momento. Con gRPC, por ejemplo, se levanta el servidor en una terminal y en otra se envían 100 mensajes de 10\,KiB:

\begin{lstlisting}[language=bash,caption={Cambio del tamaño del mensaje durante la demostración}]
python src/grpc/server_grpc.py nodo-B --silencioso
python src/grpc/client_grpc.py --sender nodo-A --receiver nodo-B --size-bytes 10240 --count 100 --run 99
\end{lstlisting}

En TCP el procedimiento es el mismo con \texttt{src/sockets/server.py --node nodo-B --port 5001} y \texttt{src/sockets/client.py}, que acepta las mismas opciones \texttt{--size-bytes}, \texttt{--count} y \texttt{--run}. Los clientes escriben sus registros en \texttt{data/}; esos archivos de demostración no forman parte de los datos entregados y no se suben al repositorio.
